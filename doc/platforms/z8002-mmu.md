# Z8002 with a paged MMU

`z8002-mmu` is a working bring-up configuration for a nonsegmented Z8002
with an external paged MMU. The standalone harness and MAME `z8002unix`
implement the same board interface and run the same machine-specific kernel.
The existing Z8001 configuration is available as `z8001-mmu`; `emulated`
remains its default compatibility name. MAME calls that machine `z8001unix`.

This is a new board design, not an Onyx hardware reproduction or the FPGA
`cpm8000_z8002` machine. It retains the existing console, clock and ATA
interfaces so the V7 drivers and upper kernel layers can be reused. The FPGA
example's banked MMU lacks the page protection, access-fault delivery and
connected timer interrupt required by this configuration.

## CPU and executable compatibility

Both machines run kernel and user C with 16-bit pointers and separate
instruction/data spaces. User s.out e707/e711 executables, libraries and
filesystem contents are unchanged. The Z8002 kernel, firmware, sector-zero
loader, standalone startup and EPU adapter are built for this machine.

A Z8002 trap saves a six-byte tag/FCW/PC frame. Its entry code adds a synthetic
map identifier so the existing C syscall, signal and saved-register interfaces
can be reused, and removes that identifier before IRET. The shared runtime
lives in `machine/z8000/krt-body.inc`, included by each CPU's `krt.s`.
MMU faults use NMI; the Z8002 has no Z8001 SEGT pin. Kernel window accesses
have explicit recovery sites; arbitrary kernel faults remain fatal.

Device-interrupt entry preserves the interrupted NVIE state on both machines.
It permits clock nesting after clock startup, while keeping it disabled during
early boot. Enabling it unconditionally could let a pending device interrupt
admit the clock before process 0's u-area was initialized.

## Memory and MMU

The CPU presents 16-bit addresses. The MMU chooses a context from system/normal
mode and instruction/data bus status, then translates through 2 KiB pages.
There are 128 table selectors, each with 32 descriptors, and independent I/D
backing selectors. Table selectors are external hardware registers, not CPU
segments. Descriptors provide unmapped, read-only and system-only protection.

Installed RAM defaults to 1 MiB, with a 20-bit physical address range. The
kernel reserves the first 192 KiB for bootstrap/kernel mappings and the top
64 KiB at `0xF0000` for the software EPU. The service also remains available
with smaller installed low RAM. Kernel allocation stops below its reservation.
Each process retains the common `0xF000–0xFFFF` u-area/system-stack window.

The common MMU ports are defined in `machine/mmu/paged/mmu.h`. The Z8002 adds:

| Word I/O port | Function |
|---|---|
| `0xD4` | Select the current normal-mode data context |
| `0xD6` | Select a context/page for the system-data aperture at `0xE000–0xE7FF`; `0xFFFF` disables it |
| `0xD8` | Select the system instruction context |
| `0xDA` | Select the system data context; bootstrap uses 3, kernel uses 1 |
| `0xBE` read | Read the selected page descriptor for validation |

User copies validate descriptors and use the privileged aperture, restoring its
previous selector before enabling interrupts. The allocator, shared text,
protection, stack-growth policy and V7 swapping mechanisms are reused.

The software EPU executes at `0x8000` in system instruction context 127.
Fixed gates in instruction page zero switch between it and the kernel, while
the kernel data map and stack remain installed. Its constants are mapped into
unused kernel data addresses. Kernel data+BSS must fit below `0x8000`;
the build and disk loader enforce that limit. Interrupts remain masked while this banked
service runs. The Zilog arithmetic engine and C trap handler are shared with
the Z8001 implementation.

## Disk bootstrap and build

The Z8002 has its own 2 KiB ROM image, built from `mame/boot/unixv7/z8002/rom.s`.
Its current payload is 664 bytes and contains no kernel or EPU image. ROM reads
sector zero; its `block.s` loads `/boot`; original V7 standalone filesystem code
then loads `/unix` and `/fpe`. Kernel instruction storage is at physical
`0x20000`, data at `0x10000`, and the PSA at kernel data address `0xD000`.
`machine/boards/unixv7/z8002/emurom.s` is a separate direct-load reset fixture for fast regressions.

From a checkout with the host bootstrap tools built:

```sh
cmake -S v7z8000/usr/sys -B tests/build/z8002-mmu \
  -DCMAKE_BUILD_TYPE=Release -DKERNEL_CONFIG=z8002-mmu
cmake --build tests/build/z8002-mmu --target test
python3 mame/build_rom.py --machine z8002unix \
  --kernel-build tests/build/z8002-mmu --output tests/build/z8002unix
python3 mame/install_boot.py tests/build/z8002-mmu/hd.img \
  tests/build/z8002unix/boot.img --build tests/build/z8002unix
```

The installer refuses to overwrite its output. Choose a fresh output name on
subsequent builds. The standalone harness boots the same disk and firmware:

```sh
cd tests/build/z8002-mmu
./test_driver -b ../z8002unix/roms/z8002unix/unix.rom \
  -d ../z8002unix/boot.img -i 'echo hello | cat\nexit\n' -x hello
```

For MAME, use the published `unixv7_demo` branch, which contains both machines
and supplies the CPU bus-status and mode-output support. Build it
with `python3 mame/build.py MAME-WORKTREE`, producing both machines. Follow
[the MAME guide](../development/mame.md) for prerequisites and CHD creation.
Launch the unified executable with `unixv7_demo z8002unix -window`, the new ROM directory and a disk prepared by
the Z8002 builder. Press Return at `: ` to load the default kernel.
The existing Z8001 ROM and kernel are not interchangeable with these images.

`mame/test.py` accepts `--machine z8002unix`, `--disk` and `--rompath`; its
RAM default becomes 1 MiB. The standalone harness accepts `-R` up to 1024 KiB.
Both use the same boot disk contents and kernel artifacts.

## Validation and remaining work

Standalone tests cover boot/pipelines, caught signals, user preemption,
large split-I/D programs, libc, combined/split floating-point vectors,
user-copy fault recovery, stack growth, protection, shared text and low-memory
swapping including delayed/failing swap I/O. Some tests allow more CPU cycles
for the Z8002's software window access and trap normalization.
MAME disk boot passes floating-point vectors and native C compile/link/execute,
plus stack growth/protection, shared text and twelve-process swapping at 320 KiB.
The existing Z8001 boot/pipeline regression also passes after the shared-runtime
refactor and interrupt-entry fix.

The Z8002 native kernel/firmware rebuild workflow has not been validated.
Multiuser startup, crash inspection and the remaining device tests need their
own machine acceptance runs. This configuration does not implement the FPGA
example's peripherals or claim Onyx hardware compatibility. MAME shares the page translation, console, clock, disk and swap implementation
with Z8001; CPU context selection and fault wiring remain in separate files.
